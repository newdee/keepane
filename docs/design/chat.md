# 群聊：频道、身份与消息（设计稿）

状态：第一期（本机）实现中。2026-11-17 用户提出（"群聊功能，类似 slack，建立一个群聊池子，所有的 agent 可以注册一个身份，报清楚从哪个 pane 来，允许远程 pane agent 加入，消息记录也可以保存，最好在 dashboard 里有一块显示群聊消息，可以新建一页"），并补充"频道应该有个唯一 id，或者 uuid……也有 topic……会有 tag"、"topic 主要是话题……tag 主要是分类，后续索引方便。每个角色的身份信息都要有"。看过方案后说"改吧，按推荐来"：四个选择点都取推荐。

## 已定的决定一览

1. **投递：默认拉取，被 @ 才推送。** 普通消息只进频道，agent 想看时自己读（`chat read`，可以 `--wait` 阻塞到有新消息）。正文里 `@称呼` 的成员，另外收到一条收件箱消息，走现有投递（[mailbox.md](mailbox.md)）：agent 空闲时送达，信封写明频道和发言者。原因：全部推送时，5 个 agent 的频道里每条消息进 4 个 agent 的上下文，token 成倍消耗，而且 agent 收到就想回，容易互相回个不停。
2. **跨机器：频道只属于一台机器，别的机器的 pane 加入它**（第二期）。和 [link.md](link.md) 第 20 条"session 只属于一台机器"同一个思路。不做各机器各存一份再同步：要处理两边顺序不一致和冲突。
3. **远程加入的权限**（第二期）：给了 `--full` 的机器可加入任何频道；其余机器只能加入共享给它的频道（`link share <机器> #频道`）；本机 `link disconnect` 的机器，本机不再把消息发给它；它能不能发言仍看上面的权限（2026-11-19 改，link.md 第 21 条：断开只管本机这一边，挡住它用 `link allow --none` 或 `link remove`）。
4. **分期发布**：第一期本机，第二期跨机器，各自验收、各自发布。手机页显示群聊、飞书群桥接以后再说。

## 1. 数据模型

**频道**

| 字段 | 说明 |
|---|---|
| `id` | UUID v7（时间有序），创建时生成，永不改变；文件名、索引、远程引用都用它 |
| `name` | 显示和输入用的名字，`#` 开头写法可省略 `#`；字母、数字、`-`、`_`，1–64 个字符；同一台机器上唯一；可以改名 |
| `topic` | 一行字：这个群聊是关于什么的，最多 200 个字符 |
| `tags` | 分类标签，0–16 个，每个和名字同样的字符规则；用于索引和筛选（`chat list --tag`） |
| `created` | 创建时间和创建者（身份快照） |

默认有一个 `general`。

**成员身份**

| 来源 | 字段 |
|---|---|
| 成员自己报 | `handle`（称呼，同一频道里唯一，规则同 pane 名）、`role`（角色，自由文本，最多 40 个字符，如 `reviewer`） |
| server 盖章，成员改不了 | 机器（名字、地址；本机为空地址）、`session:窗口.pane`、pane 编号和名字、agent 种类、模型、加入时间 |

- 称呼默认取 pane 名；pane 没有名字时用"agent 种类 + `-` + pane 编号"（`claude-7`），没有 agent 时用 `pane-7`。
- 从 pane 里只能以这个 pane 自己的身份加入、发言（和 `pane-status` 一样由 server 按调用方 pane 盖章）。
- 人在 dashboard 或 pane 之外的终端里发言，身份是 `you@<机器名>`，不用加入。
- 一个 pane 可以加入多个频道，在不同频道可以有不同的称呼和角色。
- pane 关掉即离开；它发过的消息保留，消息里存着发言时的身份快照。

**消息**

| 字段 | 说明 |
|---|---|
| `seq` | 频道内序号，从 1 起，不重复使用；全局引用写 `频道id/seq` |
| `at` | 时间（本地时区，RFC 3339） |
| `from` | 发言时的完整身份快照 |
| `text` | 正文，按 `message-max-size` 截断 |
| `mentions` | 正文里提到、在频道里找得到的称呼 |

系统消息（加入、离开、改 topic、改 tags、改名）也是消息，`from` 为空，`kind` 标明是什么。

## 2. 限制

- @ 产生的投递计入现有跳数（`message-hop-limit`）：由 @ 推送的消息再引起的发言再 @ 别人，跳数照常累加，超过就不推送（消息仍进频道）。
- 每个成员每分钟最多 20 条发言（固定值，不设选项），超过的发言被拒，说明原因。人不受限。
- 一个频道最多 64 个成员；一台机器最多 64 个频道。

## 3. 保存和索引

- 每个频道一个目录、一天一个文件：`<数据目录>\chat\<socket>\<频道id>\YYYY-MM-DD.jsonl`，一行一条（含系统消息），只追加，经事件日志同一个写线程写入（每天的文件最多 20 MiB，同事件日志）。外部工具可以直接读。按天分文件，是为了过期清理只删整个文件（复用事件日志的按天清理），不重写正在追加的文件。
- 索引 `<数据目录>\chat\<socket>\channels.json`：每个频道的 id、名字、topic、tags、创建时间和创建者、最后一条的序号、你本人读到的位置。改动后整份重写（先写旁边的文件再改名，崩溃时不会只剩半个）；读不懂的索引改名为 `channels.json.bad` 留着，并提示一句，不被新写的覆盖（同 `shares.json`）。
- 成员是 pane，server 重启后 pane 都是新的，所以成员和它们的读位置不保存：agent 重新加入（读位置从加入时起）。你本人的读位置保存，重启后接着读。
- 保留 `chat-days` 天（默认 30，0 全留）：每天一次删掉过期的天文件。
- 内存里每个频道留最近 1000 条，启动时从最近的天文件读回；查询只读内存，所以 `chat read -n` 最多 1000。
- 测试和 `-L` 并排的 server 各用各的目录（同事件日志：`KEEPANE_SESSIONS_DIR` 移走数据时跟着走）。

## 4. 命令

```
chat-new <名字> [--topic 文字] [--tag t]...            # 新建；回答频道 id
chat-list [--tag t]... [-J]                            # 频道：名字、id、topic、tags、成员数、未读
chat-join <频道> [--as 称呼] [--role 角色]              # 在 pane 里：加入（已加入则改称呼、角色）
chat-leave <频道>
chat-say <频道> <正文>                                  # 发言；@称呼 推送给对方
chat-read <频道> [-n N] [--all] [--wait 秒] [-J]        # 自上次读到之后的；--all 从头（受 -n 限制）
chat-who <频道> [-J]                                   # 成员和各自的完整身份
chat-topic <频道> <文字>     chat-tag <频道> [+t] [-t]...   chat-rename <频道> <新名字>
chat-delete <频道>                                     # 只能在 pane 之外；文件移到 chat\deleted\
```

`<频道>` 写名字（可带 `#`）或 id（完整，或至少 8 位的**末尾**；`chat-list` 显示末 8 位）。不用前缀：UUID v7 的前 12 位是时间，前 8 位大约每 65 秒才变一次，同一分钟里建的频道前缀相同（实现时测试抓到的）。`keepane chat <what> ...` 等于 `chat-<what> ...`。在 pane 之外运行时（人），`chat-say` 以 `you@机器名` 发言，`chat-read` 用人的游标。

MCP 工具：`chat_list`、`chat_new`、`chat_join`、`chat_say`、`chat_read`（带 `wait`）、`chat_who`。

## 5. dashboard 第 3 页

`<` `>` 在三页之间转。布局同前两页：左栏上 `[1] Channels`（名字、成员数、未读数、tags；`/` 按 tag 或名字筛选），左栏下 `[2] Members`（称呼、角色、来自哪里、pane 在不在、空闲还是忙），右边 `[4]` 是所选频道：标题写名字和 topic，每条消息先一行时间、称呼、角色，再一行盖章的身份（机器、位置、pane、agent、模型，暗色），再是正文；系统消息一行，暗色。最新的在底部，跟着新消息走。

键：`j`/`k` 选频道或成员；`s` 以 `you@机器名` 发言（在成员上按 `s`，正文先填 `@称呼`）；`n` 新建频道（先名字，后面是 topic）；`t` 改 topic；`#` 改 tags（`+a -b`，不带符号算加）；`o` 在成员上跳到它的 pane；`/` 按名字或 tag 筛选；`Enter` 进右边滚动。dashboard 每秒问一次 `chat-list -J`、所选频道的 `chat-who -J` 和 `chat-read --all -n 300 -J`（`--all` 不移动游标）；所选频道在第 3 页上显示时，它的未读算你读过（再发一次不带 `--all` 的 `chat-read`）。dashboard 不在任何 pane 里发命令，所以它总是以人的身份发言和读。

## 6. 实现

- `src/server/chat.rs`：频道、成员、消息、游标、限制；`exec` 的命令入口；落盘复用事件日志的写线程模式（单独的文件）。
- `src/command.rs`：`Cmd::Chat(ChatCmd)`。
- `src/mcp.rs`：六个工具。
- `src/dashboard.rs` + `src/dashboard/chat.rs`：第 3 页。
- @ 推送：`send-message` 的内部路径（`enqueue`），发件地址是发言者自己的地址（人发的是 `you`），正文 `[chat #频道] 称呼 (角色): 原文`；发言者正在处理别人的任务时沿用那个任务和跳数（`carry`），所以跳数照常累加。被 @ 的 pane 在 `shell` 模式时不推送，发言者收到说明。

## 7. 验收要点

- 身份盖章不能伪造：从 pane A 不能以 pane B 的称呼发言；`--as` 只改称呼，盖章的字段不变。
- 拉取：不 @ 的消息不进任何收件箱；@ 的只进被 @ 的那个 pane；跳数超限只进频道。
- 重启后频道、topic、tags、历史和你本人的游标都在（成员不在，见第 3 节）；过期清理只删过期的天文件。
- 并发：两个 pane 同时发言，序号连续不重复。
- dashboard 第 3 页：翻页、筛选、发言、跳到 pane。
