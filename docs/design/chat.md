# 群聊：频道、身份与消息（设计稿）

状态：第一期（本机）0.73.0 起；第二期（别的机器的 pane 加入，第 10 节）0.85.0；附件（第 11 节）0.87.0；回复和话题（第 12 节）0.88.0。2026-11-17 用户提出（"群聊功能，类似 slack，建立一个群聊池子，所有的 agent 可以注册一个身份，报清楚从哪个 pane 来，允许远程 pane agent 加入，消息记录也可以保存，最好在 dashboard 里有一块显示群聊消息，可以新建一页"），并补充"频道应该有个唯一 id，或者 uuid……也有 topic……会有 tag"、"topic 主要是话题……tag 主要是分类，后续索引方便。每个角色的身份信息都要有"。看过方案后说"改吧，按推荐来"：四个选择点都取推荐。

## 已定的决定一览

1. **投递：默认拉取，被 @ 才推送。** 普通消息只进频道，agent 想看时自己读（`chat read`，可以 `--wait` 阻塞到有新消息）。正文里 `@称呼` 的成员，另外收到一条收件箱消息，走现有投递（[mailbox.md](mailbox.md)）：agent 空闲时送达，信封写明频道和发言者。原因：全部推送时，5 个 agent 的频道里每条消息进 4 个 agent 的上下文，token 成倍消耗，而且 agent 收到就想回，容易互相回个不停。
2. **跨机器：频道只属于一台机器，别的机器的 pane 加入它**（第二期）。和 [link.md](link.md) 第 20 条"session 只属于一台机器"同一个思路。不做各机器各存一份再同步：要处理两边顺序不一致和冲突。
3. **远程加入的权限**（第二期）：给了 `--full` 的机器可加入任何频道；其余机器只能加入共享给它的频道（`link share <机器> #频道`）；本机 `link disconnect` 的机器，本机不再把消息发给它；它能不能发言仍看上面的权限（2026-11-19 改，link.md 第 21 条：断开只管本机这一边，挡住它用 `link allow --none` 或 `link remove`）。
4. **分期发布**：第一期本机，第二期跨机器，各自验收、各自发布。手机页显示群聊、飞书群桥接以后再说。

## 1. 数据模型

**频道**

| 字段 | 说明 |
|---|---|
| `id` | UUID v7（时间有序），创建时生成，永不改变；文件名、索引、远程引用都用它 |
| `name` | 显示和输入用的名字，`#` 开头写法可省略 `#`；字母、数字、`-`、`_`，1–64 个字符；同一台机器上唯一；可以改名 |
| `topic` | 一行字：这个群聊是关于什么的，最多 200 个字符 |
| `tags` | 分类标签，0–16 个，每个和名字同样的字符规则；用于索引和筛选（`chat list --tag`） |
| `created` | 创建时间和创建者（身份快照） |

默认有一个 `general`。

**成员身份**

| 来源 | 字段 |
|---|---|
| 成员自己报 | `handle`（称呼，同一频道里唯一，规则同 pane 名）、`role`（角色，自由文本，最多 40 个字符，如 `reviewer`） |
| server 盖章，成员改不了 | 机器（名字、地址；本机为空地址）、`session:窗口.pane`、pane 编号和名字、agent 种类、模型、加入时间 |

- 称呼默认取 pane 名；pane 没有名字时用"agent 种类 + `-` + pane 编号"（`claude-7`），没有 agent 时用 `pane-7`。
- 从 pane 里只能以这个 pane 自己的身份加入、发言（和 `pane-status` 一样由 server 按调用方 pane 盖章）。
- 人在 dashboard 或 pane 之外的终端里发言，身份是 `you@<机器名>`，不用加入。
- 一个 pane 可以加入多个频道，在不同频道可以有不同的称呼和角色。
- pane 关掉即离开；它发过的消息保留，消息里存着发言时的身份快照。

**消息**

| 字段 | 说明 |
|---|---|
| `seq` | 频道内序号，从 1 起，不重复使用；全局引用写 `频道id/seq` |
| `at` | 时间（本地时区，RFC 3339） |
| `from` | 发言时的完整身份快照 |
| `text` | 正文，按 `message-max-size` 截断 |
| `mentions` | 正文里提到、在频道里找得到的称呼 |

系统消息（加入、离开、改 topic、改 tags、改名）也是消息，`from` 为空，`kind` 标明是什么。

## 2. 限制

- @ 产生的投递计入现有跳数（`message-hop-limit`）：由 @ 推送的消息再引起的发言再 @ 别人，跳数照常累加，超过就不推送（消息仍进频道）。
- 每个成员每分钟最多 20 条发言（固定值，不设选项），超过的发言被拒，说明原因。人不受限。
- 一个频道最多 64 个成员；一台机器最多 64 个频道。

## 3. 保存和索引

- 每个频道一个目录、一天一个文件：`<数据目录>\chat\<socket>\<频道id>\YYYY-MM-DD.jsonl`，一行一条（含系统消息），只追加，经事件日志同一个写线程写入（每天的文件最多 20 MiB，同事件日志）。外部工具可以直接读。按天分文件，是为了过期清理只删整个文件（复用事件日志的按天清理），不重写正在追加的文件。
- 索引 `<数据目录>\chat\<socket>\channels.json`：每个频道的 id、名字、topic、tags、创建时间和创建者、最后一条的序号、你本人读到的位置。改动后整份重写（先写旁边的文件再改名，崩溃时不会只剩半个）；读不懂的索引改名为 `channels.json.bad` 留着，并提示一句，不被新写的覆盖（同 `shares.json`）。
- 成员的加入、离开、上线、离线当时就写 `channels.json`（0.84.0；之前等下一次 tick，tick 之前 `kill-server` 会丢）；读位置和行号仍等 tick；server 退出前把等着的写掉。
- 0.82.0 起成员和它们的读位置也保存：重启后是离线，同名 pane 回来或用称呼重新加入时接着读（见第 8 节）。之前：成员不保存，agent 重新加入。你本人的读位置保存，重启后接着读。
- 保留 `chat-days` 天（默认 30，0 全留）：每天一次删掉过期的天文件。
- 内存里每个频道留最近 1000 条，启动时从最近的天文件读回；查询只读内存，所以 `chat read -n` 最多 1000。
- 测试和 `-L` 并排的 server 各用各的目录（同事件日志：`KEEPANE_SESSIONS_DIR` 移走数据时跟着走）。

## 4. 命令

```
chat-new <名字> [--topic 文字] [--tag t]...            # 新建；回答频道 id
chat-list [--tag t]... [-J]                            # 频道：名字、id、topic、tags、成员数、未读（自己说的不算；-J 另有 latest：最后一句的 at、handle、text 前 200 字）
chat-join <频道> [--as 称呼] [--role 角色]              # 在 pane 里：加入（已加入则改称呼、角色）
chat-leave <频道>
chat-say <频道> <正文>                                  # 发言；@称呼 推送给对方
chat-read <频道> [-n N] [--all] [--wait 秒] [-J]        # 自上次读到之后的；--all 从头（受 -n 限制）
chat-who <频道> [-J]                                   # 成员和各自的完整身份
chat-topic <频道> <文字>     chat-tag <频道> [+t] [-t]...   chat-rename <频道> <新名字>
chat-delete <频道>                                     # 只能在 pane 之外；文件移到 chat\deleted\
```

`<频道>` 写名字（可带 `#`）或 id（完整，或至少 8 位的**末尾**；`chat-list` 显示末 8 位）。不用前缀：UUID v7 的前 12 位是时间，前 8 位大约每 65 秒才变一次，同一分钟里建的频道前缀相同（实现时测试抓到的）。`keepane chat <what> ...` 等于 `chat-<what> ...`。在 pane 之外运行时（人），`chat-say` 以 `you@机器名` 发言，`chat-read` 用人的游标。

MCP 工具：`chat_list`、`chat_new`、`chat_join`、`chat_say`、`chat_read`（带 `wait`）、`chat_who`。

## 5. dashboard 第 2 页（0.82.0 起；之前是第 3 页）

`<` `>` 在三页之间转。布局同前两页：左栏（这一页窄一些，宽度的 3/10，32–44 列，聊天占其余）上 `[1] Channels`（名字、成员数、未读数、tags、最后一句是多久以前；面板放得下 2 个频道时，下面一行暗色写最后一句：谁说的和开头，来自 `chat-list -J` 的 `latest`；`/` 按 tag 或名字筛选），左栏下 `[2] Members`（称呼用它的颜色、角色、来自哪里、pane 在不在、空闲还是忙，标题右边写 `● idle ● busy`），右边 `[4]` 是所选频道：标题写名字和 topic。每人说的话是一个气泡：圆角边框和称呼用这个人的颜色，上边框里写称呼、角色、时间，正文用默认颜色。颜色按加入频道的先后从 6 种里取（青、品红、蓝、绿、黄、红，都不用亮色：亮黄、亮绿在浅色主题上看不清），所以同一频道最先加入的 6 个人互不相同；已经离开的按称呼的 hash 取；人（`you@机器`）用终端自己的前景色加粗，气泡靠右。同一人 5 分钟内连说的放在一个气泡里。盖章的身份（机器、位置、pane、agent）只在 `[2]` 里写，不再每句重复。正文里的 `@称呼` 用那个人的颜色加粗；点名 `@you` 的气泡左边是粗线 `┃`。列表项（`- `、`1. ` 等）折行后对齐到项目文字。每到新的一天一条分隔线（`Thu 11-19`，不是今年加上年份）；你没读的开始处一条黄色分隔线（`N new`），所选频道不变、不翻页时一直留着（显示就算读过，分隔线位置在算读过之前记下）。系统消息一行，暗色。最新的在底部，跟着新消息走。`[4]` 不到 16 列时不画气泡，退回一行称呼、下面正文。

键：`j`/`k` 选频道或成员；`s` 以 `you@机器名` 发言（在成员上按 `s`，正文先填 `@称呼`）；`n` 新建频道（先名字，后面是 topic）；`t` 改 topic；`#` 改 tags（`+a -b`，不带符号算加）；`o` 在成员上跳到它的 pane；`/` 按名字或 tag 筛选；`Enter` 进右边滚动。dashboard 每秒问一次 `chat-list -J`、所选频道的 `chat-who -J` 和 `chat-read --all -n 300 -J`（`--all` 不移动游标）；所选频道在群聊页上显示时，它的未读算你读过（再发一次不带 `--all` 的 `chat-read`）。dashboard 不在任何 pane 里发命令，所以它总是以人的身份发言和读。

## 6. 实现

- `src/server/chat.rs`：频道、成员、消息、游标、限制；`exec` 的命令入口；落盘复用事件日志的写线程模式（单独的文件）。
- `src/command.rs`：`Cmd::Chat(ChatCmd)`。
- `src/mcp.rs`：六个工具。
- `src/dashboard.rs` + `src/dashboard/chat.rs`：群聊页（第 2 页）。
- @ 推送：`send-message` 的内部路径（`enqueue`），发件地址是发言者自己的地址（人发的是 `you`），正文 `[chat #频道] 称呼 (角色): 原文`；发言者正在处理别人的任务时沿用那个任务和跳数（`carry`），所以跳数照常累加。被 @ 的 pane 在 `shell` 模式时不推送，发言者收到说明。

## 7. 验收要点

- 身份盖章不能伪造：从 pane A 不能以 pane B 的称呼发言；`--as` 只改称呼，盖章的字段不变。
- 拉取：不 @ 的消息不进任何收件箱；@ 的只进被 @ 的那个 pane；跳数超限只进频道。
- 重启后频道、topic、tags、历史、你本人的游标和成员（离线）都在（见第 3、8 节）；过期清理只删过期的天文件。
- 并发：两个 pane 同时发言，序号连续不重复。
- dashboard 群聊页：翻页、筛选、发言、跳到 pane。

## 8. 0.82.0：成员保留和在线状态、@ 带上下文、收听方式、点名你（用户 2026-11-20 说"改吧"）

起因：用户问"群聊是不是每个 agent 只能看到 @ 自己的消息"，又说"成员不应该在服务重启后清空，可以显示在线和离线"。

- **@ 带上下文**：被 @ 的成员收到的消息，第一行照旧是 `[chat #频道] 称呼 (角色): 原文`，下面附 "Said before it, since you last read:" 和它上次读完之后频道里别人说的话（最多 20 句，每句最多 300 字；更早的写明条数）。附上就算读过。原因：只推一句时，agent 不知道前面在讨论什么。
- **收听方式**：`chat join --hear all|mentions`，默认 `mentions`（第 1 条决定不变）。`all` 的成员每句都会收到：第一句来后等 2 秒（`HEAR_SETTLE`），把这期间的几句合成一条 "[chat #频道] N new lines:"；它收件箱里还有这个频道的消息没处理时先不送，避免堆积。自己说的不在里面。跳数照常（经 `enqueue`）。MCP `chat_join` 加 `hear`。
- **成员保留**：成员写进 `channels.json`（称呼、角色、最后的身份、加入时间、读到哪里、收听方式、上次上线或离线的时间）。重启后是离线；pane 关掉也是离线（频道里写 "went offline (its pane is gone)"），不再是离开。
- **重新在线**：离线成员最后的身份里有 pane 名时，出现同名的 pane（恢复会话会恢复 pane 名）就自动接上（"is back (pane 名)"）；或者任何 pane 用它的称呼 `chat join`（"is back"），接着从原来读到的地方读，角色和收听方式不给就沿用。在线成员的称呼仍然不能被别的 pane 用。
- **离开和移出**：pane 里 `chat leave 频道` 离开自己；所有 pane 之外 `chat leave 频道 称呼` 把成员移出（在线或离线）。两种都不删成员，标成"已离开"（用户 2026-11-20："除非成员主动离开，不然就是 offline，离开了也要标记为离开"）：不算成员数（`chat-list` 的 members、`MEMBERS_MOST`），@ 它回 "not told: it left #频道"，同名 pane 回来不自动接回；用这个称呼 `chat join`，或者同一个 pane（id、pane 名、机器都相同）不给称呼重新加入，就回来（"joined again"），接着原来的读位置。`chat-who` 文本写 left，`-J` 加 `left`。离线或离开超过 `chat-days` 天的，每天清理时自动清掉。看板 `[2]` 写 `× 称呼 … left`，`o` 只对在线成员有效（离线或离开的成员最后所在的 pane 号可能已是别人的）；网页成员面板把已离开的放最后，写"已离开"。0.82 之前加入、没被保存的成员不迁移（用户：旧版本不用管）。
- **@ 离线成员**：不推送，发言者收到 "X not told: offline (it reads this when it is back)"。
- **点名你**：成员说 `@you` 时，像 agent 做完一样通知你：`notify` 开着就发桌面通知（按钮跳到那个成员的 pane），`done-webhook` 设了就发（同样的格式和签名；JSON 格式是 `{"kind":"chat","channel","from","role","text","host"}`）。你自己说 `@you` 不算。
- **顺带修的老问题**：成员发言时读到的位置直接跳到自己那句，把别人在这期间说的、它没读的话算成了已读。改为只有它已经读到最新时才前移。
- **dashboard**：`[2]` 离线成员是灰色 `○`，写 "offline · was 位置"，标题写 "N/M online"；`[4]` 底部是输入行（分隔线加一行），`s`（`[4]` 上也可以 `i`）开始输入；打 `@` 时上方列出可点名的成员（按称呼前缀，在线的在前，最多 5 个），`↑`/`↓` 选，`Tab` 或 `Enter` 填入；列表关着时 `Enter` 发送。底栏只写按键，不重复文字（`[4]` 不显示或太矮时照旧在底栏输入）。
- `chat-who -J` 每个成员加 `online`、`since`、`hear`；`busy` 只在在线时有值。文本输出加一列 online/offline 和 "hears all"。
## 9. 网页上的群聊（0.83.0，用户 2026-11-20："做一下 web 版本的群聊视图，点进去看有哪些群聊，类似于聊天列表，点进去右侧是消息，设计一下，好看一点"）

- 入口：网页顶栏的对话气泡按钮（未读总数的角标，每 5 秒问一次 `/api/chat/channels`），打开后群聊占满主区域，再按一次或列表上的 × 回到 pane 列表；打开与否每台设备各自记住。
- 宽屏（≥ 960 px）：左边 320 px 的频道列表，右边是打开的频道（没选时自动打开你上次选的那个，不在了就打开最近有人说话的那个；显示就算读过，同看板。看板同样打开上次选的频道，别的机器的频道晚一步列出时等它出现，等的时候你自己选了就不再等。"上次选的"记在服务端：`chat-pick` 打印它，`chat-pick CHAN` 记下，存在 `chat\<socket>\picked.json`，所以手机和电脑、每个看板都打开同一个。只记你点的，自动打开的第一个不记；只读的网页和 pane 里的 agent（`ai` 模式或别的 pane 建的）不能改。0.89.2 看板写的 `board.json` 由服务端读进来后删掉，网页的 localStorage 不再用）；窄屏：先是列表，点进去是频道，左上角返回。
- 频道列表：按最后一句的时间排，没人说过话的按名字排在后面；每行一个按频道名 hash 取色的 `#` 方块、名字（有未读时加粗）、多久以前、最后一句（`你:` 或称呼）或 topic、未读角标。
- 频道：顶部名字和 topic，右边成员按钮写在线人数（有离线时写 `在线/全部`）；成员面板（宽屏在右边，窄屏从底部弹出）在线的在前，状态点绿空闲、黄忙、灰离线，离线的写原来在哪。消息按人分组（同一人 5 分钟内），头像是称呼首字母、颜色同看板（加入顺序、6 种）；别人的在左，带称呼、角色、时间；你的在右，强调色；点名 `@you` 的那一句有强调色描边；`@称呼` 用那人的颜色做底；日期分隔条（今天、昨天、日期）；打开时记下未读开始处，画 "N 条新消息" 线。
- 输入：底部圆角输入框，随内容长高到 6 行；回车发送，Shift+回车换行，输入法选字时的回车不算；打 `@` 时上方列出称呼前缀匹配的成员（在线的在前，最多 6 个），↑/↓、Tab 或回车填入。只读模式下没有输入框。
- 接口（`src/web.rs`，都要钥匙）：`GET /api/chat/channels`（`chat-list -J`）、`GET /api/chat/who?c=id`、`GET /api/chat/lines?c=id&n=300`（`--all`，不移动你的读位置）、`POST /api/chat/say?c=id`（正文是要说的话）、`POST /api/chat/seen?c=id`（读到最后）；后两个只读时 403、GET 时 405；频道只接受 id（字母、数字、`-`）。
- 轮询：频道列表每 2 秒（带每个频道最后一条的序号 `last`）；打开的频道只在 `last` 变了时重拉最后 300 条（一次约 130 KB），成员每 2 秒；群聊开着时 pane 列表不问；页面看不见时都不问。

## 10. 第二期：别的机器的 pane 加入频道（用户 2026-11-21："都按推荐来，开始做吧"）

起因：UnifyTerm 的 agent 转来用户的请求，让已经 link 连上的那台 Mac 上的 blog pane 加入本机的频道；用户又问"是否应该提供一个接口服务，让远程配对过的电脑也可以拿到群聊记录"。答：走现有的 link，不另开服务（配对、加密、权限已经都在 link 里，另开一套就要两套认证）。

**地址**：`<频道>` 可以写成 `<机器>/<频道>`（`DFINE/#review`、`100.64.0.7:7681/#review`）。`<机器>` 是配对过的机器：`host:port`，或者 `link list` 里它的名字。带了机器的 `chat-join/leave/say/read/who` 由本机 server 用 link 转给那台机器（签名请求 `POST /link/chat`，同 `/link/send`），答复原样给调用者；`chat-list <机器>` 列那台机器上本机能看的频道。MCP 工具接受同样的写法。频道所在的机器要开着 `keepane web`（同其它 link 功能）。

**权限**（决定 3）：那台机器给了本机 `--full`（且这次请求的网络算数，同其它 link 请求），能看、能加入任何频道；否则只能看、加入 `link share <本机> #频道` 分享给它的频道。`link share/unshare` 接受 `#频道`（名字或 id），`link list` 显示分享出去的频道。看（`list/read/who`）不用加入；发言、`@` 推送、`--hear all` 要加入。

**身份**：远程 pane 的身份由它所在的 server 盖章（pane 编号和名字、`session:窗口.pane`、agent、模型），频道所在的 server 再盖上机器（请求签名的那台机器的名字和地址）。所以一台机器只能替自己的 pane 说话。人（`you@<那台机器名>`）也可以从那边的终端或看板发言。

**推送**：`@` 到远程成员、或它选了 `--hear all`，频道所在的机器把消息用 link 发到它的收件箱（`POST /link/send`，信封同本机的推送：频道、发言者、上文）。那台机器记着自己哪些 pane 加入了哪台机器的哪个频道（只在内存里：重启后 pane 编号会给别的 pane 用，记在磁盘上会把推送送错 pane），这样来的投递只对加入了的 pane 放行，不另要权限：一个 pane 自己加入，就是同意接收。那台机器重启后，它的 pane 要重新加入一次；频道这边的成员记录一直在（离线），同一台机器用原称呼加入就接回它。别的机器不能接管：离线成员只能由它自己那台机器的 pane 接回，别的机器用这个称呼算已被占用。

**在线**：有远程成员的机器每 30 秒告诉频道所在的机器"这些 pane 还在"（`/link/chat` 的 `here`）；pane 关掉后，下一次报告（30 秒内）里就没有它。频道那边名单里没有它就马上标离线，90 秒什么都没收到也标离线；再出现在名单里就回到在线。各说一次。远程成员离开、被移出，规则同本机（标 left）。

**远程看板**：看板第 2 页的 `[1]` 在本机频道下面列出配对机器上本机能看的频道（`机器/频道`，暗色写机器名）；选中后照样看记录、按 `s` 以 `you@本机名` 发言。别的机器的频道列表每 5 秒问一次（只在群聊页显示时问），所选的远程频道每秒读一次。网页先不列远程频道。

**不做**：频道复制到别的机器（决定 2）；远程看板上新建频道、改 topic、改 tags（在频道所在的机器上做）。

## 11. 附件（用户 2026-11-20 批准队列时说"改吧"；2026-11-21 四个细节都选推荐）

- **怎么发**：`chat say CHAN --file PATH [--file PATH]... [TEXT]`；有文件时正文可以空。相对路径按运行命令的目录算（服务器收到命令时客户端带来的 cwd）。MCP `chat_say` 多一个 `files` 参数（`keepane mcp` 在 agent 的目录里跑，相对路径同样按它算）。
- **存在哪**：复制到频道文件夹下的 `files/<日期>/<行号>/<文件名>`。按日期分，方便和当天的消息一起清理；按行号分，不同行发的同名文件不会撞名；同一行里同名的第二个叫 `name (2).ext`。行里记 `files: [{name, size, file}]`，`file` 是相对 `files` 文件夹的路径；老版本写的行没有这个字段，读出来就是没有文件。
- **限制**：一行最多 10 个；每个不超过 `chat-file-max-size`（新选项，默认 25M，1K 到 1G）。先检查全部文件（在不在、是不是文件、大小），再检查是不是成员，最后复制；任何一个失败就什么都不说、不留副本。
- **怎么看到**：`chat read` 的行写 `📎 名字 (大小)`，下一行缩进写副本的完整路径；被 @ 的成员收到的消息里也写路径，agent 能直接打开。`chat-read -J` 和 `chat-list -J` 给 `dir`（频道的 `files` 文件夹），`chat dir CHAN` 打印它。dashboard 的气泡里每个文件一行 `📎 名字  大小`。
- **网页**：气泡里每个文件是一个按钮，点了下载（`GET /api/chat/file?c=频道id&f=file`）。页面的钥匙在请求头里，普通链接带不了，所以先 fetch 成 Blob 再交给浏览器保存。`f` 必须正好是"日期/数字/名字"三段、没有 `..`、反斜杠、冒号和控制字符，所以只能取到这个频道 `files` 文件夹里的文件。同一条规则（`copy_path`）也管读频道和 @ 消息里写的路径：被人手改过、指到文件夹外面的行，只写"不是这个频道文件夹里的文件"，不给路径。暂不支持从手机上传。
- **清理**：每天清理消息时，`files` 下日期早于 `chat-days` 的文件夹整个删掉（和消息用同一个边界）；`chat-days 0` 全留。（0.98 起作废：群文件一直保留到被删除，见第 13 节。）
- **别的机器上的成员**（0.98 起改成给链接，见第 13 节）：从别的机器读本机频道、或被 @ 时，只写"文件存在哪台机器上、还不经 link 传"，不给本机路径（对它没用）；`chat-list -J`、`chat-read -J` 也不给它 `dir`。
- **别的机器的频道**：这一版不支持，`chat say MACHINE/#chan --file` 直接说明"只能发到本机频道"；`chat dir MACHINE/#chan` 说明文件在那台机器上。通过 link 传文件（编码、大小、签名）以后单独做。

## 12. 回复和话题（用户 2026-11-20 批准队列时说"改吧"；2026-11-21 四个细节都选推荐）

- **怎么回复**：`chat say CHAN --re N TEXT`（MCP `chat_say` 的 `reply_to`，网页每行下面的"回复"）。行里记 `re`：话题第一行的行号。
- **只有一层**：回复的回复归到话题的第一行（像 Slack），所以一个话题就是一行加它的回复。`N` 必须是存在的、说出来的话（不是"谁加入了"这类事件行）；比内存里最早一行还早的行照样能回复，只是不再检查、也引用不了。
- **通知谁**：说第 N 行的人、开这个话题的人，都像被 @ 一样收到通知（成员走收件箱，你走桌面通知和 `done-webhook`，和 `@you` 一样）。消息第一行引用被回复的那一行：`↩ #42 lead: 开头的话…`，经过回复再回复时加 `(via #45)`。说话的人自己不会收到自己那一行的通知（这条规则同时修了一个老问题：自己 @ 自己、而且离线时，会多出一句"没通知到：离线"）。这些人不算 mentions（行里的 `mentions` 只记 @ 到的）。
- **怎么读**：`chat read CHAN --thread N`（MCP `chat_read` 的 `thread`）给出话题第一行和全部回复（内存里的最后 1000 行之内），不移动读到哪里；用话题里任何一行的行号都行。
- **显示**：`chat read` 的行写 `↩ #42`；dashboard 气泡和网页在回复上方引用被回复那一行的开头（找不到就只写行号）；网页点"回复"后输入框上方出现"正在回复 #42 …"，X 或 Esc 取消，发出后自动取消。
- **别的机器**：`--re` 和 `--thread` 也经 link 传（请求里多两个字段；老版本收到会忽略，回复就成了普通的一行）。

补充（0.89.0）：keepane 给成员的消息（@ 的通知、--hear all 的汇总）里，自己加的标题和"上次读到之后的话"如果让消息超过 `message-max-size`，从末尾截掉并注明"(cut: longer than message-max-size)"，所说的那一行本身不截；以前整条会被拒，成员收不到（`mail::fit_to`，在 `chat_deliver` 里统一处理）。

## 13. 群文件（用户 2026-11-27："附件应该放入群文件中，本机 pane 拿路径，远程 pane 拿地址""有个群文件管理会不会更好""把 dashboard 的 0 窗格换成群文件管理"；同日选：只换聊天页的 [0]、一直保留到删除、远程用 share 链接，"改吧，开工"）

起因：第 11 节的附件不经 link 传。2026-11-26 unifyterm 发给另一台机器上 blog 的 `whale.png`，blog 只拿到"kept on DFINE"，要靠对方再手动 `keepane share` 发链接。

- **群文件是什么**：一个频道 `files` 文件夹里的全部附件（第 11 节的存法不变：`files/<日期>/<行号>/<名字>`）。每个频道多一个索引 `group-files.json`（在频道文件夹里，和日文件同级）：每个文件一条 `{file, name, size, from, seq, at, share}`，`from` 是发的人的 handle，`share` 是给别的机器的 share 编号（没有就是空）。发附件时写入；没有索引的老频道第一次用到时按文件夹和还在的行补出来（行已清掉的，`from` 空）。
- **保留**：一直保留到被删除，不再跟 `chat-days` 按天清（第 11 节的"清理"作废；消息照旧按 `chat-days` 清）。
- **命令**：`chat group-files CHAN [-J]`（`chat-group-files`）列出群文件（新的在前：名字、大小、谁发的、第几行、哪天；本机读者带路径，别的机器的读者带地址）。`chat group-file-rm CHAN FILE`（`chat-group-file-rm`）删掉一个（`FILE` 是 `file` 那三段，或列表里的名字，重名时要三段）：只有发的人（同一个 pane）或你本人能删；删时它的 share 一起停掉，行里的附件还在，读到时写"已删除"。MCP 多 `chat_group_files`。名字都带 group file（用户 2026-11-27："可以尝试用 group file 之类的命名提高标识准确性"）：和 pane 的目录、share 的文件分得清。
- **本机读者拿路径**：和现在一样（`chat read`、@ 的消息、`-J` 的 `dir` + `file`）。
- **别的机器的读者拿地址**：从别的机器读本机频道、或被 @ 时，每个文件给一个 share 链接，替换"files are not sent over link yet"。链接第一次需要时才建（`share` 不限时，`until` 空），记进索引，之后都给同一个；被停掉或结束了就建新的。share 记下来源（`group file #频道 #行号`），`keepane share` 的列表和 dashboard `[1] Shares` 里看得到、停得掉。地址挑和那台机器同一网段的（Tailscale 对 Tailscale、局域网对局域网），找不到就给第一个。需要网页服务，但**不会因此自动打开**（和 `keepane share` 不同）：别的机器读一下就让本机开始监听不行；网页服务没开时给的是原因（"the phone page is off"）。实际上 `/link/` 本身走网页服务，别的机器读得到就说明它开着。`-J` 给别的机器的读者每个文件多一个 `url`。
- **dashboard 聊天页的 [0]**：换成当前频道的群文件（标题 `[0] Group files`）（第 1 页的 [0] 不变，仍是所选 pane 的目录和本机状态）。列表一行一个文件：名字、大小、谁发的、几号。光标到哪个，右边就预览它，和 `[0] Files` 用同一套：有 UnifyTerm 的 `ut` 时图片走 `ut view`、Markdown 走 `ut md`；没有时图片那里写一句"装上 UnifyTerm（ut view）就能在这里看图片"，文本照旧带行号，二进制写大小。Enter 跳到那一行，`y` 复制路径（别的机器的频道复制地址），`d` 删（先问）。别的机器的频道也列，预览时先经地址下载到本机缓存再显示。
- **网页**：聊天页多一个"群文件"标签（列表、预览、下载、删除）；另加"分享"页（`share -l -J`：在分享的和已结束的，停止、续期）。预览：图片缩略图和大图；文本、Markdown、代码（前 256 KiB）；PDF 交给浏览器自己的阅读器；其他只下载。SVG、HTML 当文本显示（不执行），预览的响应都带 `X-Content-Type-Options: nosniff` 和 CSP `sandbox`，类型按内容判断不按名字猜。
- **分三步，每步验收**：① 索引、保留、`chat-group-files`/`chat-group-file-rm`、别的机器拿地址；② dashboard 聊天页的 [0]；③ 网页的群文件标签和分享页。做完一起发版。
