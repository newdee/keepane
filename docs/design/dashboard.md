# Dashboard：lazygit 式的多面板（0.17）

用户要求（2026-09-26）：dashboard 改成 lazygit 那样的面板格式，显示更多信息，更好控制。

## 1. 旧版的问题

0.15 的 dashboard 是上下两段：上面一张窗格表，下面一块随按键切换的视图（事件、消息、任务、屏幕、历史）。

- 同一时刻只能看一样东西：看收件箱就看不到屏幕，看任务就看不到窗格的事件。
- 能做的事只有管理排队消息，而且要先按 E 进"管理模式"；给窗格发消息、改名、改模式、解卡、跳过去、关掉，都得退出去敲命令。
- 窗格只有模式、忙闲、收件数、在做什么；目录、程序、多久没输出、起了多久都看不到。

## 2. 布局

```
┌─[1] Panes  3 · 1 busy · 2 queued ─┐┌─[0] %4 tester · ai · busy ── Screen │ Scrollback │ Events │ Detail ─┐
│ work                              ││ $1:@3.%4  claude  /home/me/proj  up 12m  quiet 3s               │
│> 0.1 %4 tester   ai  busy   2  3s ││ doing: "tests 3/10"      working on #12                         │
│  0.0 %2          -   -      0  1m ││──────────────────────────────────────────────────────────────── │
│ ops                               ││ (所选窗格此刻的屏幕，带颜色)                                       │
└───────────────────────────────────┘│                                                                 │
┌─[2] Inbox %4 · 2 ─────────────────┐│                                                                 │
│> #12 user   5s  run the tests     ││                                                                 │
│  #13 %lead  1s  then report back  ││                                                                 │
└───────────────────────────────────┘│                                                                 │
┌─[3] Tasks ────────────────────────┐│                                                                 │
│  #12 running  %4  2 steps  run …  ││                                                                 │
└───────────────────────────────────┘└─────────────────────────────────────────────────────────────────┘
 s send  r rename  m mode  R ready  o go there  x close  Enter screen  / filter  ? keys  q quit
```

- 左列三个面板：[1] 窗格（按会话分组）、[2] 所选窗格的收件箱、[3] 任务。右边 [0] 是主面板，四个标签：Screen（此刻的屏幕，带颜色）、Scrollback（连回滚）、Events（这个窗格的事件）、Detail（所选消息的全文与去向，或所选任务的每一步）。
- 左列宽约 40%（30–60 列）。窗口窄于 70 列时只显示焦点所在的一侧。
- 聚焦的面板边框加亮；底行是聚焦面板能用的键，或提示、输入框、确认框。

## 3. 按键（lazygit 的习惯）

| 键 | 作用 |
|---|---|
| Tab / Shift+Tab，1 2 3 0，h / l | 换面板 |
| j / k，↑ / ↓ | 在列表里移动；在主面板里滚动 |
| [ / ] | 主面板换标签 |
| PgUp / PgDn，g / G | 主面板翻页、到顶、到底 |
| Enter | 窗格 → 主面板看屏幕；收件箱 → 这条消息的 Detail；任务 → 这个任务的 Detail |
| / | 筛选窗格 |
| ? | 全部按键 |
| q，Esc | 退出（Esc 先取消输入框、确认框） |

窗格面板上：`s` 给它发消息（底行输入，Enter 发送）、`r` 改名、`m` 改工作模式（菜单）、`R` 解卡（`pane-ready -t`）、`o` 跳过去（`focus-pane`，在弹窗里就顺带关掉 dashboard）、`x` 关掉（`kill-pane`，10 秒内 `u`/`prefix u` 可撤销）。
收件箱面板上：`d` 删除、`K` / `J` 上下移、`t` 放到最前、`u` 撤销删除。

鼠标：点面板聚焦，点行选中，滚轮在指针所在的面板里滚。

## 4. 安全

旧版"只看不动、要先按 E"的做法取消，换成按后果分级：

- 可撤销、只影响元数据的（改名、解卡、跳过去、发消息、调顺序）直接做，底行说做了什么。
- 删除排队消息、关掉窗格、把窗格切到 `shell` 模式（从此收到的文字会被当命令执行）先弹确认框，`y` 才执行。删除有 `u` 撤销，关窗格有 undo-kill。
- dashboard 发出的命令只有 `QUERIES`（看）与 `ACTIONS`（做）两张表里的；测试逐键检查：不在表里的命令一条也发不出去，需确认的命令不经确认发不出去。
- 服务端的规则不变：从窗格里只能改自己窗格的模式——dashboard 在弹窗里跑，弹窗不属于任何窗格，所以能改任何窗格（与在窗格外敲命令相同）。

## 5. 刷新

每秒（或按键后立即）问四样：窗格表（`list-panes -a -F`，比旧版多了目录、pid、起始时间、最后输出时间、尺寸、退出码）、所选窗格的收件箱、任务表、主面板当前标签的内容。所选窗格按编号记住，窗格增减时不跳。
