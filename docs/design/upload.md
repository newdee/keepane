# 网页上传文件到 pane 的目录（0.66）

用户说「在web版中加一个文件上传的入口，上传后默认存在当前pane路径的指定文件夹下面」；方案给出后「改吧，按推荐来」。

## 用户看到的

- 手机网页（`keepane web`）的 pane 底栏，输入框旁一个 📎 按钮：选一个或几个文件，逐个上传，显示进度；传完列出每个文件存到的完整路径，带"复制路径"按钮。
- 存到这个 pane 当前目录下的 `uploads/`（不存在就建）。选项 `set -g web-upload-dir uploads`：相对路径相对于 pane 的目录，绝对路径就固定存那里（`~` 展开）。
- 同名不覆盖：`report.pdf` 已有就存成 `report (1).pdf`，依次往上。
- 单个文件默认最多 2 GiB：`set -g web-upload-max 2G`（和 `link-agents-limit` 同样的写法）。超过的在开始传之前就拒绝（413）。
- 状态栏和 show-messages 说一句：`%3: received report.pdf (2.1M) in C:\proj\uploads, from 192.168.1.20`。
- 传完不把路径打进 pane（避免误触发命令）。

## 不做 / 拒绝

- `--read-only` 启动的网页：按钮不显示，接口回 403。
- 另一台机器复制过来的 pane（`#{pane_machine}` 不为空）：接口回 400。按钮照常显示，点了用提示说出原因（不灰掉：手机上灰掉的按钮点不了，看不到为什么）。以后要做得走 link。
- 文件夹上传、断点续传：不做。

## 安全

- 文件名只取最后一段（`/` 和 `\` 都算分隔符），换掉控制字符和 Windows 不允许的字符（`histlog::safe_name`），去掉结尾的点和空格；空名、`.`、`..` 拒绝；Windows 保留名（CON、NUL、COM1…，带不带扩展名）前面加 `_`。
- 名字最长 200 字节（Linux 的上限是 255 字节，还要留给 ` (12)`），在字符边界上截，较短的扩展名保留。
- 必须带 `Content-Length`：分块发送（`Transfer-Encoding: chunked`）的回 411，否则会把它当成 0 字节，写一个空文件冒充。
- 被拒时（错 key、超大小、只读……）剩下的请求体不超过 1 MiB 就先读掉再回复：不读就关闭会变成 RST，浏览器只看到"网络错误"，看不到原因。
- 写文件用"新建、已存在就失败"（`create_new`），换下一个名字再试，两个上传同名也不会互相覆盖。
- 边收边写盘，不整个读进内存；传一半断了，删掉写了一半的文件，回 400。
- 每次读之间最多等 60 s，超过就当断了。
- 网页本来就要求 key（`X-Keepane-Key`）。拿到链接的人能往这台机器写文件，所以上面这些限制都是必需的。普通 HTTP：局域网里能被抓包看到，和网页现在显示的屏幕内容一样；Tailscale 地址没有这个问题。

## 接口

- `POST /api/upload?pane=%N&name=<文件名>`，请求体就是文件内容，`Content-Length` 必须有。
- 回 JSON：`{"path": 完整路径, "name": 存成的名字, "bytes": 字节数}`。
- `GET /api/upload-info?pane=%N`：`{"dir": 会存到的目录, "max": 字节数}`，或拒绝的原因。网页打开 pane 时先问好：手机只在点按的那一下打开文件选择框，不能等请求回来再开；也好在发之前就按上限挡住太大的文件。
- 服务器端：网页进程用已有的本地查询拿 pane 的目录（`#{pane_current_path}`）、`#{pane_machine}`、两个选项；写完用隐藏命令 `web-uploaded` 告诉 server，由它写状态栏和 show-messages。
