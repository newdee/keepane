# 时钟：等你处理的事、手机网页的二维码（0.67）

用户说「可以想一下本地还有什么可加的」；给出 5 个方向后选「125吧」。第 5 个（pane 所在仓库的 git 状态）实际已经有了：时钟和状态栏在分支后面显示 `main ●3 ↑2 ↓1 !1`（README「git」一节）。提议时漏看了，已向用户说明，只做 1 和 2。

## 用户看到的

- 时钟（prefix t）日期和其他时区下面，黄色一行 `needs you: …`，覆盖所有 session：
  - 先列等你的 agent：`work:1.0 claude waits`。条件和 Trace 的"等你"一样：pane 读得到 agent，而且它最后一次 `pane-wait` 比 Trace 里最新的一步还新（`Server::waits_for_you`，trace-pane 和时钟共用）。
  - 再列有标记的窗口，和状态栏一致：`!` bell、`@` message、`#` activity、`~` silence，写成 `work:2 bell`。
  - 放不下时列到放得下为止，后面写 `+N`；一个都放不下就截断第一个，保留 `+N`。
  - 没有要处理的就没有这一行（原来的各行不变）。
- 手机网页开着时，时钟最后一行（keepane 那行）末尾加 `· p: phone page`。
- 时钟下按 `p`：网页的二维码盖在时钟中间，下面一行 `phone page · a key hides it`（只读时写 `(read-only)`）。
  - 颜色固定为黑底白块，不随主题变（浅色主题下按主题颜色画会变成反色二维码，很多手机相机读不了）。
  - 再按 `p`、按别的键（那个键照常起作用，`q` 照样退出）、按前缀键（`C-b d` 脱离时不能把二维码留在屏幕上），或者 60 秒后，二维码消失。是否还在显示只有一条规则（`clock::qr_left`），画面和 `p` 都按它；服务器每秒的 tick 本来就重画，所以最晚 61 秒消失（实测 60.6 秒），不另外安排帧。
  - pane 太小放不下：写 `too small: the QR code needs W×H`（34 列，80 列终端左右分屏的 40 列 pane 放得下，不被截断），不把带 key 的网址用文字写出来。
  - 网页没开：写 `the phone page is off: keepane web starts it`。

## 安全

- 二维码里有网页的 key，拿到就能操作 pane。所以只在按 `p` 时显示，60 秒或按键后就收起，不会一直留在屏幕上（时钟常被当屏保挂着）。
- 同一个 session 的其他客户端同样会看到，这和 `keepane web` 启动时打印二维码、dashboard 的分享二维码一样。

## 不做

- 股票等需要联网的数据：用户放弃了（时钟只显示本机数据）。
- 收件箱里排队等 pane 处理的消息：那是等 pane 的程序，不是等人；消息到了没人看的窗口已经由 `@` 覆盖。
