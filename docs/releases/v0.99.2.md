## An ssh that cannot connect says why

### New
- When a window's `ssh` cannot connect, its window still closes, and a box now shows what ssh said (`Connection refused`, `Permission denied`, a host key not accepted). Press `r` to connect again in a new window, or `q` to close the box. This holds for any window or pane whose program is `ssh` itself (`choose-ssh`, `new-window ssh host`) when it ends with ssh's own error (exit 255), or with another failure within 10 seconds. An `ssh` typed into a shell does not close the pane and shows no box.

### Fixed
- When a pane's program exits, keepane now waits until its last output has been read (at most half a second). Before, the exit could be handled first and the last lines were lost: `remain-on-exit`'s note could come before what the program printed.
- On macOS and Linux, a character whose bytes arrive in two reads (a Chinese character typed through an input method, over SSH) now waits up to 500 ms for its other bytes. Before, after 30 ms its bytes were taken as separate characters and the rest was dropped. A lone Escape still waits 30 ms.

### Changed
- CI runs the tests with more threads (12 on Linux and macOS, 6 on Windows), runs fmt and clippy beside the tests, and the release builds Linux and macOS beside Windows, for shorter waits. The same tests run on the same systems.
